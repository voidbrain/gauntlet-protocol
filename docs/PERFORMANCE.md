# Performance measurements

Use `run --telemetry --fresh` for new performance evidence. Functional pack execution remains bounded by its case/suite/output budgets. Metadata reads, sampler overhead and bounded residency cleanup are additional measured/explicit overhead, not free inference. No model inference is needed to validate code/fixtures.

Direct Ollama telemetry requests NDJSON streaming. The report retains provider load/prompt/generation/total milliseconds, prompt/output counts, derived generation tokens per second and client time to first generated token. That first token may be thinking output; it is not necessarily first visible answer latency. Reasoning text and raw responses are not retained. Missing provider metrics remain null. Alternative non-streaming adapters currently retain measured case latency and usage; unsupported timing fields remain null rather than estimated.

A suite-resident profile keeps the model loaded between cases. The first case is marked cold-model only when initial Ollama inventory confirmed absence; this is model loading, not a claim that disk/OS caches are cold. Subsequent cases reuse residency. There is no extra unbudgeted warm-up generation. A previously resident model is not unloaded by Gauntlet. If the suite introduced residency, bounded empty-prompt unload cleanup is attempted and its released/unknown state is recorded; shared-service restart/force-kill is never used. External runtime residency is owner-managed. Concurrent users can affect residency and all performance figures; use an otherwise idle runtime for controlled comparisons.

The host sampler targets 500 ms (configurable 250–10000 ms), also samples at case boundaries and after cleanup, never overlaps its own probes, and caps samples at 10000. Reports preserve actual sample timestamps, sampler duration/error counts, baseline/final observations and sampled peaks. Short spikes can be missed; these are not guaranteed hardware high-water marks.

On POSIX hosts, RSS/CPU sums cover the listening daemon and descendants. RSS can count shared pages more than once; ps CPU is a moving-average utilization, not instantaneous per-case CPU. System free memory/load are OS observations. On Apple Silicon, IOAccelerator device utilization and in-use allocation are whole-device counters including desktop/other apps. Ollama size_vram is provider model allocation. Unified-memory allocations overlap RAM; never add these numbers as independent memory pools. Unknown PID, denied host probes and unsupported counters remain null. No sudo, background daemon or global runtime variable changes are introduced.
