# Local runtime adapters

Ollama remains the default. `profile.backend` can select `ollama`, `llama.cpp` or `mlx-lm`; endpoints must be credential-free loopback roots. Adapters attach to an already configured local server. They install/start/download nothing. Runtime compatibility is tested with neutral HTTP fixtures; a particular real installation is unverified until its own campaign runs.

For llama.cpp and MLX-LM, provide `runtimeManifest`: version/build label, modelDigest, exact server context, local artifacts (`path`, `sha256`), nullable serverFingerprint and supportsThinking. A single artifact uses its file SHA256 as modelDigest; multiple artifacts use SHA256 of JSON.stringify of the ordered SHA256 array. Include weights, tokenizer/config and relevant runtime artifacts. Every file is verified before generation, then file metadata is checked for mutation. The live requested model must already appear in `/v1/models`. llama.cpp additionally verifies live `/props` context/template/defaults. Model identity and an explicitly declared server fingerprint must match the completion response.

These are owner-reviewed manifests and local artifact checks, not authenticated proof that an arbitrary server loaded those exact files. Run servers offline with fixed artifacts/settings; do not allow automatic fetching. Runtime manifests/context and permissions remain the owner's responsibility. Reports replace local artifact paths with digest identifiers; the saved profile is identity evidence, not a runnable substitute for the original local configuration.

Requests use `/v1/chat/completions`, one completion, bounded max_tokens, explicit non-null temperature/top-p/top-k/seed and optional chat_template_kwargs.enable_thinking when the manifest establishes support. A server context mismatch, unsupported thinking, absent usage, truncation or unexpected model/fingerprint fails closed. Prompt tokens plus reserved output must fit the declared context. No automatic fallback from one runtime/provider to another. Alternative server residency is externally managed; per-case unload profiles are rejected.

Different weight conversions/quantizations are distinct configurations. Compare quality together with cold/warm latency, throughput, memory, context and resource limits. Do not attribute a configuration difference solely to the engine. Native Apple Silicon does not imply Neural Engine use or guaranteed superiority.

Primary contracts inspected: [Ollama chat](https://docs.ollama.com/api/chat), [Ollama inventory](https://docs.ollama.com/api/ps), [llama.cpp server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md), [MLX-LM server](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/server.py). Source inspection is not live model acceptance.
